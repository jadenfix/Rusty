# Using Rusty from first launch to returning later

Read in this order. The practical guides include checks you can perform yourself.

1. [Install and verify](install.md): prerequisites, source install, PATH, updates and rollback.
2. [Configure and connect](configure.md): credentials, provider/model identity, saved preferences and precedence.
3. [Read and control the terminal](terminal.md): skins, cmux panes, draft input, progress, menus and interruption.
4. [Work and verify](work.md): shell commands, profiles, permissions, goals, side discussions and integrations.
5. [Connect repositories and tools](integrations.md): Git hosts, project remotes, authentication checks and MCP server setup.
6. [Quit and return](sessions.md): fresh conversations, resume, previews, locks and project identity.
7. [Understand saved data and resources](data.md): transcripts, memory, credentials, cleanup and resource limits.
8. [Recover when something goes wrong](troubleshooting.md): concrete symptoms and the next useful check.
9. [Reference and documentation checks](reference.md): accepted values, evidence levels and maintenance commands.

The command examples describe the code in this checkout. A source review, an
offline test, a terminal recording and a real provider response answer different
questions. [Demo provenance](../demo/README.md) identifies each recording's build;
older clips do not prove a newer UI or provider works. The [audit checklist](audit.md)
keeps the remaining human and resource checks explicit.
